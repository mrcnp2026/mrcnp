# 사무실 근태관리 — 앱 코드

기획 문서는 `근태관리\01 빌드 프롬프트\`에 있다 (이 폴더로 복사하지 않는다). 진행 상태는 `근태관리\CURRENT_STATUS.md`.
문서 우선순위: **부록(1.5판) > ①②③ 본문**.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 앱 켜기 — http://localhost:4123 |
| `npm run verify` | 자동 검사 전체 (계정 없이 도는 것 + 열쇠가 있으면 권한 회귀 검사) |
| `npm run verify:rls` | 권한 회귀 검사만. `SUPABASE_DB_URL`이 없으면 **실패**한다. 마이그레이션 적용 후 매번 (부록 R-12-6) |
| `npm run check:db` | 열쇠 파일(`.env.local`)이 제대로 들어갔는지 확인 |
| `npm run db:apply -- <파일>` | 마이그레이션 1개를 한 트랜잭션으로 적용 (적용 뒤 `verify:rls`) |
| `npm run admin:invite -- --no <사번> [--name 이름]` | **비상 관리자 초대** (부록 R-2의 4). 첫 관리자 만들기도 이것으로 |
| `npm run e2e:login` | **로그인·출퇴근 기기 확인** — 실제 Chrome(가상 지문 인식기)으로 비밀번호 만들기·로그인·출퇴근 기기 등록·출퇴근·다른 기기 차단·비밀번호 변경·기기 해제·로그인 초기화 (검사 계정 `e2e-audit`·`e2e-audit2`를 잠깐 켠다. 앱이 켜져 있어야 한다) |
| `npm run e2e:gate3 -- <관리자 초대 링크>` | (예전 방식: 폰 등록) 실제 Chrome + 가상 인증기로 등록·로그인 확인, 360px 캡처 (⚠️ 사번 `test` 직원을 만든다 — 이미 있으면 실패) |
| `npm run audit:overflow` | **가로 넘침 검수** — 모든 화면 × 폭 7가지(320~1280) × 영어·한국어. 화면을 고칠 때마다 (사번 test를 잠깐 관리자로 바꿨다 되돌림) |
| `npm run i18n:export` | 번역 검수 표(CSV) 내보내기 → `checks/번역-검수.csv` (부록 R-15) |

## 열쇠 파일

`.env.sample`을 복사해 `.env.local`로 저장하고 값을 넣는다. `.env.local`은 git에 올라가지 않는다.
`SUPABASE_SERVICE_ROLE_KEY`는 서버 전용이다 — `src/lib/supabase/admin.ts`만 쓰고, 이 파일은 브라우저 코드에서 import하면 빌드가 실패한다.

## 데이터베이스

- 프로젝트: Supabase `출퇴근관리`, **서울 리전**(`ap-northeast-2`) — 부록 R-1
- 표 만들기 파일: `supabase/migrations/` (번호 순서대로, 이미 적용한 파일은 고치지 않는다 — R-12-6)
- 권한 잠금 세 겹:
  1. 브라우저 로그인 세션은 **읽기 정책만** 있다 (직원은 자기 것, 관리자는 전체)
  2. 브라우저 쪽 역할(anon·authenticated)에서 **쓰기 권한 자체를 회수**했다
  3. **트리거**: 서버도 `punch_events`를 고치거나 지우지 못한다. 정정·연장·패스키 표는 사실 칸을 못 바꾼다
- 기록을 쓰는 것은 서버 API(`service_role`)뿐이다 (마스터 6장 1.3판)

## 알려진 한계 (마스터 지시로 여기에 적는다)

- **사무실 WiFi 확인은 완전한 대리 출근 방지가 아니다.** WiFi가 닿는 곳(주차장·옆 건물)에서도 찍힌다. 목표는 재택·외부 출근 기록을 걸러내는 것이다.
- **출퇴근 기기 1대 고정은 엄밀하지 않다.** ① 기기의 지문 확인은 그 기기의 화면 잠금 PIN으로도 통과되고, 그 기기에 지문을 등록해 둔 다른 사람도 통과한다 — 폰을 통째로 맡기고 PIN까지 알려 주면 대리 출근이 된다 (폰으로 찍는 방식은 어느 서비스나 같다. 완전히 막으려면 출입구 지문 단말기가 필요하다). ② 아이폰·안드로이드의 패스키는 같은 사람의 애플·구글 계정 안에서 다른 기기로 동기화될 수 있다 (등록 때 `user_passkeys.backed_up`에 기록만 한다, 4-11). ③ 첫 기기는 본인이 직접 등록하므로, 아직 등록하지 않은 직원이 비밀번호를 넘기면 동료의 폰이 그 직원의 출퇴근 기기로 등록될 수 있다 — 직원 상세의 기기 종류·등록일로 확인한다.
- **출퇴근 기기 등록은 앱 주소(도메인)에 묶인다.** 배포 도메인을 바꾸면 전 직원이 출퇴근 기기를 다시 등록해야 한다 (관리자가 해제 → 직원이 재등록). 비밀번호 로그인은 영향이 없다.
- **등록한 기기가 맞는지의 화면 안내는 브라우저에 남긴 표시(localStorage)로 한다.** 브라우저 데이터를 지우면 등록한 폰에서도 "이 기기에서는 찍을 수 없습니다"가 한 번 뜬다 — "이 기기가 등록한 기기입니다"를 누르면 지문 확인으로 넘어간다. 진짜 확인은 서버가 기기의 서명으로 한다.
- **미기록 배너는 직원이 앱을 열어야 보인다.** 며칠 앱을 안 연 직원에게는 그동안 안 보이므로 관리자 화면의 '미기록' 표시가 함께 필요하다 (7-8).
- **서버는 생체정보를 받지 않는다.** 지문·얼굴 확인은 폰 안에서 끝나고, 서버에는 공개키·서명 횟수·기기 종류만 저장된다.
- **비밀번호를 잊으면 스스로 되찾을 수 없다.** 직원 계정에 이메일·문자 인증이 없어서다. 관리자가 초대 링크를 다시 보내면 직원이 새 비밀번호를 만든다.
- **로그인 실패 안내**: 아이디가 없는 것·비밀번호가 틀린 것·퇴사한 것을 구분해 알려 주지 않는다 (누가 직원인지 새지 않게). 같은 아이디로 15분에 10번 틀리면 그 아이디의 로그인을 잠깐 막는다.

## 로그인 방식 (2026-10-05 의뢰인 결정 — 마스터 8-3·4-11을 대체)

**로그인은 아이디(사번, 또는 등록된 휴대폰 번호) + 비밀번호, 출퇴근 찍기는 등록한 기기 1대 + 지문·얼굴.**
로그인(조회·신청·관리자 화면)은 PC·폰 어느 기기에서나, 여러 기기에서 동시에 된다. 출퇴근 버튼만 본인이 등록한 기기에서 그 기기의 지문·얼굴·PIN 확인을 거쳐야 찍힌다 — 비밀번호를 동료에게 알려 줘도 동료 폰으로는 대신 찍지 못한다 (`/api/punch`는 로그인 세션 + 본인 기기의 패스키 서명을 둘 다 요구한다).

- **출퇴근 기기 등록**: 직원이 자기 폰에서 로그인한 뒤 홈 화면의 「이 기기를 출퇴근 기기로 등록」을 직접 누른다 (초대 코드 없음, `/api/device/register/*`). 직원당 1대 (`one_active_passkey`).
- **기기 바꾸기**: 관리자가 직원 상세 「관리 › 출퇴근 기기 해제」(사유 필수) → 직원이 새 폰에서 다시 등록. 이것이 "기기 변경 승인"이다. 본인 것은 스스로 해제하지 못하지만, 관리자가 혼자면 허용한다.
- 등록하지 않은 기기에서 열면 출근 버튼 대신 "등록한 기기에서만 찍을 수 있습니다" 안내가 나온다.

- **처음 한 번**: 관리자가 보낸 초대(링크·8자리 코드·QR) → `/register`에서 직원이 비밀번호를 직접 정한다 → 바로 로그인. 초대는 한 번만 쓰인다.
- **비밀번호**는 Supabase Auth가 보관한다 (이 앱의 표에는 없다). 계정 이메일은 받는 사람이 없는 `{사번}@staff.invalid`. 규칙은 8자 이상 (`src/lib/login-rules.ts`).
- **바꾸기**: 로그인한 뒤 「내 계정」(`/punch/account`). 바꾸면 그 기기만 남고 다른 기기는 모두 로그아웃된다 (`profiles.sessions_revoked_at`).
- **잊었을 때**: 관리자가 직원 상세에서 링크를 다시 보낸다.
- **분실·유출**: 관리자가 직원 상세 「관리 › 로그인 초기화」 — 모든 기기 로그아웃 + 비밀번호 무효 + 출퇴근 기기 해제. 본인 것은 스스로 못 한다 (R-2의 2).
- **지문 로그인**: 출퇴근 기기로 등록한 그 기기에서는 로그인 화면 맨 아래 작은 버튼으로 비밀번호 없이도 로그인된다 (보조 수단). 예전에 폰 등록만 해 둔 사람(비밀번호 없음)은 「내 계정」에서 비밀번호를 만들면 다른 기기에서도 로그인할 수 있다.

## 배포 (게이트 9)

- 주소: **https://mrcnp-saas.vercel.app** (Vercel 팀 `mrcnp`, 프로젝트 `mrcnp-saas`). 출퇴근 기기 등록(패스키)이 이 주소에 묶인다 — 주소를 바꾸면 전 직원이 출퇴근 기기를 다시 등록해야 한다 (비밀번호 로그인은 그대로 된다, B-13)
- GitHub `mrcnp2026/mrcnp`의 `main`에 올리면 자동 배포된다. 이 PC의 로컬 브랜치는 `master` → `git push origin master:main`
- ⚠️ Vercel 무료(Hobby) 팀은 **팀 멤버가 아닌 사람이 만든 커밋의 배포를 막는다(BLOCKED)**. 그래서 이 저장소의 커밋 작성자는 `mrcnp2026`으로 설정해 두었다 (`git config user.name/user.email`, 저장소 단위)
- 서버 열쇠: Vercel → Settings → Environment Variables에 `NEXT_PUBLIC_SUPABASE_URL`·`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`·`SUPABASE_SERVICE_ROLE_KEY`(sensitive)·`APP_ORIGIN`. `SUPABASE_DB_URL`은 서버에 두지 않는다 (PC 검사용)
